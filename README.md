# Dashboard Example

Учебный проект дашборда на React + TypeScript + Vite.

Приложение состоит из двух страниц: **панель мониторинга** с метриками и графиками
и **управление маршрутами** — таблица маршрутов с поиском, фильтрами и CRUD-операциями.

## Стек

- **React 19** — UI-библиотека
- **TypeScript** — типизация
- **Vite** — сборщик и dev-сервер (HMR из коробки)
- **React Router** — клиентский роутинг
- **Recharts** — графики (линейный и кольцевой)
- **ESLint** — линтинг

## Быстрый старт

```bash
# Установка зависимостей
npm i

# Настройка переменных окружения (см. раздел ниже)
cp .env.example .env

# Запуск dev-сервера
npm run dev

# Сборка для продакшена
npm run build

# Предпросмотр продакшен-сборки
npm run preview

# Линтинг
npm run lint
```

## Переменные окружения

Настройки API задаются через переменные окружения. В репозитории есть шаблон
`.env.example` — скопируйте его в `.env` и при необходимости измените значения:

| Переменная | Назначение |
| --- | --- |
| `VITE_API_BASE_URL` | Базовый адрес API (например, `https://dummyjson.com`) |
| `VITE_API_URL_PATH` | Путь к эндпоинту с данными дашборда (например, `/c/66ef-...`) |

Итоговый URL запроса собирается как `VITE_API_BASE_URL + VITE_API_URL_PATH`
(см. `src/pages/dashboard/DashboardView.tsx`). Файл `.env` добавлен в `.gitignore`,
поэтому коммитится только `.env.example`.

## Страницы и возможности

### Панель мониторинга (`/`)

- **KPI-карточки** — ключевые метрики с дельтой и подписью, цвет дельты
  зависит от направления (`accent` / `error`).
- **График пассажиропотока и инцидентов** — линейный график (`FlowChart`)
  с двумя осями Y.
- **Кольцевая диаграмма** — распределение по видам транспорта (`DonutChart`).
- **Журнал событий** — список действий с цветовой маркировкой типа события
  (`LogLine`).
- Дата и время в заголовке обновляются каждую секунду.

Данные загружаются с мок-API по `VITE_API_BASE_URL` + `VITE_API_URL_PATH`.
Пока данные не пришли (или запрос не удался), списки отображаются пустыми —
ошибка логируется в консоль. До появления API в качестве образца структуры
ответа использовался `src/data/dashboardData.json`.

### Управление маршрутами (`/data`)

- **Таблица маршрутов** — номер, направление, водитель, вид транспорта, статус,
  пассажиропоток, рейсы, дата обновления.
- **Поиск** по номеру, названию или водителю.
- **Фильтры** по статусу и виду транспорта, а также сброс фильтров.
- **Пагинация** (по 6 строк) и **выбор строк** с массовым удалением.
- **Добавление и редактирование** маршрута через модальную форму
  (`RouteFormModal`) с валидацией обязательных полей.
- **Удаление** с подтверждением в модальном окне.

Логика работы с данными (типы, фильтрация, добавление/обновление/удаление)
вынесена в `routeRegistry.ts`. Данные хранятся в локальном состоянии React
и инициализируются из `src/data/dataControlData.json`.

### 404 (`*`)

Любой неизвестный маршрут отображает `NotFoundView`.

## Архитектура

- **Роутинг.** `BrowserRouter` + `Routes` в `src/App.tsx`. Страницы
  подгружаются лениво через `React.lazy` + `Suspense`, что включает
  код-сплиттинг: тяжёлая библиотека графиков (`recharts`) уезжает в отдельный
  чанк и не загружается на старте.
- **Общие компоненты** (`src/shared/`) переиспользуются между страницами:
  `Header`, `Card`, `Modal`, `CustomButton`.
- **Данные.** Дашборд работает с мок-API, реестр маршрутов — с локальным
  состоянием на основе JSON.
- **Стили.** Обычные CSS-файлы рядом с компонентами, плюс глобальные токены
  в `App.css` / `index.css`.
